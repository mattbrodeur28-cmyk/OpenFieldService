# ADR-0008: Adopt Salesforce Lightning Design System (SLDS)

Date: 2026-11-26
Status: Accepted
Feature IDs: UI-001, UX-006, M1 workspace

## Context and constraints

The owner wants OpenFieldService to have Salesforce's layout and feel and has
directed adoption of the Salesforce Lightning Design System (SLDS). The app is a
single Preact runtime with Radix primitives and shared CSS design tokens
(ADR-0001/0002). Tailwind and a second rendering runtime are explicitly deferred, so
SLDS must be adopted as design tokens and CSS classes, not as Lightning Web
Components (which would introduce a second component framework).

SLDS is BSD-3-Clause licensed and redistributable with attribution. Salesforce's
"Salesforce Sans" font is not bundled; the SLDS system-font fallback stack is used.

## Options

- **Adopt SLDS design tokens + component CSS** (chosen): map the app's semantic tokens
  (`--bg`, `--text`, `--primary`, `--radius`, …) to SLDS values, then adopt `.slds-*`
  layout/component classes on the workspace shell and record pages incrementally.
- **Adopt SLDS wholesale as the only stylesheet**: highest fidelity, but rewrites every
  component class and risks a large unvetted diff and bundle growth in one step.
- **Continue the bespoke token system**: fails the owner's explicit request.

## Decision

Adopt SLDS incrementally on the existing Preact runtime:

1. Map `src/client/tokens.css` to SLDS design tokens (brand blue `#0176d3`,
   gray `#f3f3f3` page background, gray text scale `#181818/#444444/#747474`,
   4/8/12 px radii, SLDS font stack).
2. Add the SLDS stylesheet dependency and adopt `.slds-*` classes for the workspace
   shell, page header, cards, buttons, tabs, tables and record pages as bounded slices.
3. Keep the Radix primitives; apply SLDS visual classes on top rather than replacing
   the accessible dialog/tab/menu behavior.

## Consequences

- Immediate, app-wide "Salesforce feel" from the token remap; primary actions turn
  Salesforce blue and pages use the SLDS gray background.
- One more dependency and some CSS bundle growth; the full SLDS stylesheet should be
  loaded only when needed.
- Salesforce Sans is substituted with the system font stack; visual fidelity to
  Salesforce typography is approximate.

## Migration and rollback

- Token remap is a CSS-only change; revert by restoring the previous `tokens.css`.
- SLDS component classes are adopted per-screen behind the existing shared UI system;
  each slice ships independently and can be reverted independently.

## Validation and revisit triggers

- `pnpm build` and `pnpm exec tsc --noEmit` must pass; visual review is owner-performed
  (browser testing remains deferred).
- Revisit if SLDS adoption conflicts with ADR-0001's shadcn/ui component wrappers or
  the deferred Tailwind decision.
