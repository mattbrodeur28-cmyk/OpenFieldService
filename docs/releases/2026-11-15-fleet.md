# Native Fleet and maintenance pilot

Fleet now has vehicle identity (fleet number, VIN, plate, make/model/year), active/
out-of-service/retired status, miles/kilometers and attributed odometer readings.
Each vehicle links exactly one existing truck location. Assigned technician is the
same native location custody; saving both shares one transaction and optimistic
versions. Vehicle inventory opens that exact location with original stock/history.
A linked truck cannot change to a warehouse. Retirement requires empty stock.

Owner/Admin manages vehicles, assignment and maintenance. A mapped active technician
reads only their assigned vehicles; HR has no elevated Fleet access. Existing Inventory
custody edits immediately affect Fleet access. No new duplicate technician/material
master or copied vehicle stock count exists. Stock link and distance unit are fixed
once created; odometer cannot decrease without a future reviewed correction workflow.

In-app maintenance plans trigger on date and/or odometer with warning thresholds,
using the current company date. Recording completion retains immutable actor/cost/
reading/notes/before-after evidence and advances recurring dates from service date,
and mileage from service odometer. One-time plans deactivate. Replayed service IDs
return the original result; changed payload conflicts. Plan IDs are client-generated
so creation retries conflict without creating a duplicate. A service cost is not a
supplier payment, AP bill or QuickBooks posting.
